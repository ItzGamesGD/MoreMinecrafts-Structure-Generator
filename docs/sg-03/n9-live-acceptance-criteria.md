# SG-03 N9 — live acceptance criteria (fixed before any N9 run)

Environment: a real Minecraft 26.3 dedicated server running the **built production jar** (`runJarServer`, no lab mod) on a **fresh** world (seed 173), SG-03 datapack installed, and a real graphical Minecraft client (Xvfb, Mesa lavapipe Vulkan, native `Screenshot.grab`) connected over TCP. Player input that counts as live is input the client receives from the X server (xdotool): keyboard, mouse buttons and mouse look. Server commands (`/tp`, `/summon`, `/locate`) are allowed to set up a scenario but a scenario that is only verified by a server command is labelled SERVER-ONLY, not LIVE.

| ID | Scenario | PASS requires | If not achievable |
|---|---|---|---|
| L1 | Fresh world, client joins, world renders | client log shows the renderer started and the world joined; server lists the player; native screenshot not blank (more than 1,000 distinct colours) | BLOCKED |
| L2 | Natural SG-03 structure found | `/locate structure moreminecrafts:forgotten_kingdom/central_cavern` returns a position in a world generated during this run; its start exists in the saved region (not `/place`d) | BLOCKED |
| L3 | Approach and entry by the player | the player, teleported to a surface point 60–120 blocks away, ends with a position inside a piece box of the structure; the final approach (at least 20 blocks) is done by real keyboard input and verified by position change; native screenshots of the exterior and the entrance | LIVE PENDING if keyboard input does not move the player |
| L4 | Traversal of the dungeon | the player walks at least 3 successive connected pieces by real keyboard input, each leg verified by the server-side player position entering the next piece box; screenshots at each | LIVE PENDING for legs that fail; each leg reported separately |
| L5 | Room connections / accessibility | for all consecutive piece pairs of the structure the Jigsaw connection is satisfied in the saved world (pieces' connectors adjacent, doorway cells passable); this is a SERVER-ONLY check and is labelled so | — |
| L6 | Combat | a hostile mob summoned in front of the player is killed by the player's real mouse-click attacks (left click events through the client), verified by the mob dying and the player's attack statistic or the mob's health history | LIVE PENDING |
| L7 | Trial Spawner behaviour | with the real player inside a trial chamber the trial spawner block entity leaves its inactive state and spawns mobs (state/`spawn_data` read via `data get block`) | LIVE PENDING (SERVER-ONLY observation otherwise) |
| L8 | Terrain integration | native screenshots of the surface above and the cave openings near the structure show no visible hole, floating block or abrupt cut; judged from the images and from the saved column data (no air gap pillar above pieces) | PARTIAL if only screenshots |
| L9 | Geode and monster-room interaction | for each cancelled feature recorded by the guard during the run, a screenshot of the location and the saved cells show no vanilla geode/monster-room blocks inside a protected piece; at least one natural geode and one natural monster room away from the structure are also screenshotted to show normal features still generate | PARTIAL |
| L10 | Stability | no client or server crash; no `Can't keep up` message from the server and no client stall longer than 5 s (client log frame/tick markers) during the scenarios; server tick time stays under 100 ms mean | FAIL if violated |

Verdict rule: PASS only if L1–L4 and L10 pass LIVE and L5–L9 pass at their stated level; any scenario that can only be demonstrated by a server command is reported as SERVER-ONLY/LIVE PENDING, and the stage verdict is then PARTIAL, never PASS. No synthetic placement (`/place`) is used anywhere in N9.
